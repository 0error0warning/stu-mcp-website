# 首页文字居中核对（2026-10-28）

用户用横屏平板截图中的 Dock 中轴指出：首页大标题、副标题和两行说明文字看起来不齐，要求按普通段落的文字居中核对，其他位置基本齐，不再调整。

## 修正范围与事实澄清

- 原首页从 `.hero-full` 继承 `text-align: center`，大标题并不是只做了外框居中。此前用连字符相对页面中轴的位置推断标题不齐是不恰当的：不同字母宽度不等，连字符位置不代表完整字符串中心。
- 上一轮为副标题添加的零宽标点悬挂，改变了完整文字行参与居中的宽度。本轮删除该包装与样式，恢复完整文本含标点参与排版。
- 对大标题、副标题、说明和脚注明确声明 `text-align: center; text-indent: 0`。脚注从基线的 inline-flex 改为普通 block 段落，保留现有字体、字距、字号和换行设计。
- 不对大标题做像素位移；不改 Dock、按钮、插画、后续区块。本轮实际可见变化主要在副标题标点重新参与居中；不能声称每处文字位置都曾错误或都发生移动。

## 验证方法与范围

验收测的是文本节点的 Range / 每个字符的行内矩形，按行合并后比较 `(left + right) / 2` 与页面中轴，不是测父元素外框。包含普通标点的字宽，不把字形黑色像素重心、连字符或字数中点当作段落中心。

- WebKit 26.6（Windows Playwright，非真实 iPad）：390、1280、1440px，逐字符聚合。所有文字行 `text-align: center`；最大中点偏差 0.41px，无页面横向溢出。1280px 大标题 -0.16px、副标题 -0.25px、说明 0px、脚注 -0.04px。
- Chrome 1280px：大标题、副标题、脚注各 -0.008px，说明 0px。
- 截图 `docs/qa/text-centering/tablet-webkit.png` 和 `tablet-webkit-guide.png` 已视觉检查；蓝线仅临时注入浏览器用于验收，不进入产品代码。
- `npm run build` 通过。这次只改 HTML/CSS，不增加模拟实现逻辑的单元测试。
