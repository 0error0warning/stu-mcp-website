## 后续连续渲染修复 · 2026-10-26

首版静态截图验收漏掉了连续动画的残留像素，也未检查画廊选中时所有邻卡的边界。根据浏览器评论补充以下修复和回归：

- 物理画布之前通过透明色 `fillRect` 重画旧区域，无法擦掉旧像素。现在先清除同一像素对齐区域再绘制，透明与半透明背景均正确。
- 修复前，真实 engine 的 `clear` 和 `reset` 各留下 2,962 个旧像素，半透明背景 alpha 累积到 253–255；修复后旧像素为 0，背景 alpha 稳定为 64。
- 修复 601–760px 舞台为 212px、画布却最少 260px 的错配。浏览器验证：709px 与 390px 下两侧画布均为 212px，1440px 下均为 300px，底边与舞台一致。
- 画廊卡宽按静止及三个选中状态的整组边界计算，保留边缘空间，取消硬裁切。390 / 709 / 1440px 下共九种选中状态均检查所有三张卡片，无裁切、无横向溢出。
- 修复光学按钮 CSS 尺寸不变、显示密度变化时背缓冲不更新的问题。真实 WebGL 按钮 CSS 保持 220×60，DPR 1→2 后缓冲从 220×60 更新为 440×120。
- 小角色保持至少 2x 画布密度，高密度屏最高 3x，性能适配不再降至 1x；启用高质量位图平滑。实际浏览器验证为 2x。
- 开启全部角色的鼠标眼神跟随。真实鼠标事件左右切换时，1,468 个眼睛像素发生变化。当前 709px 窗口自动角色数由 2 个增加到 8 个；大屏通常为 14 个，手机初始为 6 个。
- 删除“小形状可以拖一拖”提示，保留桌面拖拽与键盘交互。

可复现的真实画布回归页位于 `tests/physics-render.html`（本地 dev 服务打开）。7 项检查全部通过：清空、重置、透明度、实色恢复、眼神跟随与清晰度、真实动画残影、WebGL 密度变化。动画用例经过 34 个真实帧、16,629 个移动像素后，与清空后同姿态全量重绘比较，残留像素和 alpha 差异均为 0。测试页的画布读回优化提示是浏览器性能建议，产品页面没有该读回逻辑。

## 全幅弧面与场景生命周期 · 2026-10-26

根据后续浏览器反馈，两个窄物理区域已移除，改为覆盖整个首屏的单画布。读取实际 `.horizon` 椭圆的 DOM 几何，并把上半弧接入真实接触求解器；角色靠重力和低摩擦向两侧滚滑，旧矩形底板在此模式下禁用。数量改为手机 4 / 中屏 6 / 大屏最多 10，半径改为 28 / 34 / 42，鼠标跟随比例为 60%。

- 正常动效首次加载不再显示静态落地占位图，角色仅从全宽顶部进入。
- 实际画布像素回读：1440px 下角色从顶部（最早可见 y=0）移动到黄弧；落地后最大实测侵入约 0.073px，黄弧下方超过 6px 的角色像素为 0。709px / 390px 下该像素数也均为 0；无横向溢出，CTA 命中正确，手机实际触摸滑动通过。
- 滚动到 FAQ 再返回、模拟 document visibilitychange 隐藏再返回，保持同一个 canvas、生成计数和种子，场景不重播。重新加载的两个种子实际为 91742 / 14250；新种子也随机旋转顶部发射序列，避免落点模式总相同。
- 物理层停稳后允许侧边整堆休眠；鼠标和滚动不对屏外画布重绘，眼神变化使用局部重绘。
- `node --test tests/ellipse-ground.test.mjs` 4/4 通过：左右自然外滑且不穿地、浅坡不滞留、旧矩形模式兼容、边墙堆稳后可休眠。此检查加入 GitHub workflow。
- 原有 7 项实际画布回归再次全部通过，包括眼神跟随、残影清除、透明度和按钮 DPR 变化。

## 默认关闭掉落与运行期开销 · 2026-10-26

最新设置取代上面阶段中的自动掉落：每次打开页面默认关闭，尚未添加开启按钮。保留可选物理实现，未来按钮可调用 `setHeroCharactersEnabled(true)`。

- 桌面初次打开：物理容器子节点 0、物理 canvas 0、物理引擎网络请求 0；滚动及重新加载后仍关闭。调用未来按钮接口后 canvas 为 1，关闭后为 0。
- 已加载的等高线、光球、画廊与安装按钮，经来回滚动及模拟 document visibility 隐藏/返回后，实际 DOM 实例均保持同一个。这里模拟了页面可见性事件，没有声称覆盖真实操作系统切后台。
- 等高线只绘静态帧；光球、安装按钮、卡片与连接虚线改为交互时播放。光球悬停 0.5 秒实际绘制 62 次；安装按钮聚焦 0.4 秒绘制 50 次，移动指针后仍可保持键盘聚焦与动画。画廊方向键切换、安装指令实际剪贴板逐字比对通过。
- 大型模糊云层静止，绿点不再循环重绘阴影，标签漂浮一轮后静止；手机去除头部/标签/首屏底栏的背景模糊。卡片逐个观察，筛选替换后的三张卡片均重新加入观察；屏外和后台循环暂停。原外部 collector SVG 的小幅动画仍保留，由其自身处理 reduced motion，不在父文档的视口暂停范围内。

同一隔离 Chromium / 1440×1000 / dev 页面，以原生 WebGL draw 调用、已连接 2D clear 调用和 CDP Performance 取样。每个区段取 3 秒，修改前预热 2.5 秒、修改后等有限入场结束预热 8 秒；这是一轮本机诊断，不是标准 FPS、GPU 时间或用户设备性能基准。清屏调用可能一次一帧多次，不能当帧数。

| 区段 | 修改前连续绘制调用 | 修改后空闲连续绘制调用 | 修改前 / 后主线程 TaskDuration |
| --- | --- | --- | --- |
| 首屏 | 等高线 268；物理清屏 1,889 | 0 | 2,131 / 274 ms |
| 连接示意 | 光球 358 | 0 | 1,312 / 1 ms |
| 原则画廊 | 0 | 0 | 1,102 / 30 ms |

不能从这些取样推导所有设备都达到某个流畅度。页面仍保留短入场、主插画动画及交互反馈。没有添加阻塞式载入动画：它不能减少已定位的持续渲染、重复初始化和重绘成本，页面内容直接显示。

生产构建的 390×844、DPR 2 触摸模拟：首屏及滑过所有 shader 区段后 canvas 仍为 0，相应 shader 模块网络请求为 0；真实 CDP 触摸滑动、筛选、问句/安装复制、画廊点击与三张卡边界、FAQ 均通过。无横向溢出、页面异常 0。reduced motion 下 canvas 0、运行 DOM 动画 0。生产桌面首次 Tab 正确落在跳转链接。

`npm run build` 和 4 项真实弧面求解器回归通过。本次未改底层渲染器，未重复宣称旧 7 项像素测试是本轮新测。过程脚本和原始输出位于忽略的 `output/playwright/performance-*` 与 `perf-*`。
