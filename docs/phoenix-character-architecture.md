# 凤凰角色系统设计决策

日期：2026-10-27。状态：设计提案；仅“脸颊语义映射与协调反应”已落地，其他模块不应视为已实现。范围为独立网站本地开发，不部署。

## 目标与当前缺口

部件独立是骨架能力，交互的单位是角色意图。左右脸颊可以有不同的触点，但应触发同一个被摸脸反应，方向影响躲闪，表情保持整体一致。独立眨眼、单侧翅膀挥动具有合理的局部含义；单颊独自泛红不作为默认反应。

当前实现是 SVG 分组 + 每通道弹簧 + 预设目标序列。能连续打断，但不是完整角色系统：没有骨骼长度约束、落脚点、受力传播、路径形变、方向素材、统一动作混合；CSS、DOM dataset 和 RAF 仍共同拥有部分视觉状态。继续堆预设无法解决这些问题。

## 建议分层

输入适配 → 意图/注意力 → 动作提议 → 姿态混合 → 骨架/接触约束 → 渲染。

1. **输入适配**：Pointer Events / 键盘统一生成 tap、stroke、grab-start、grab-update、release、cancel。事件含目标部位、角色局部坐标、世界坐标、时间、速度和 pointerId。使用 pointer capture；处理 pointercancel/lostpointercapture；移动阈值区分点击与拖拽。移动端保留页面纵向滚动，拖动策略独立校验，不能给整个首页 touch-action:none。
2. **意图与注意力**：角色持有关注对象、兴奋度、疲劳度、触摸强度、最近互动等连续变量。输入映射为 affection、reach、balance、follow、explore 等意图。待机按上下文和冷却挑选，不固定轮播，也不每次碰一下都全身响应。
3. **动作提议**：动作输出目标姿态、目标速度、参与通道、权重、包络、接触条件，而不直接改 DOM。行为可由短动作片段、程序轨迹、鼠标目标或身体反馈产生。短片段负责艺术表现，连续变量负责适应环境。允许小型接触模式（站立/迈步/被拿起/落地），但模式切换不重置姿态。
4. **混合与仲裁**：基础姿势、行走、呼吸、注视、表情、手势、拖拽分别是层。表达组保证眼睑/嘴/双颊一致，方向与细小时间差仍可独立。拖拽取得相关运动链的控制权；踩地约束不可被装饰动作覆盖。按通道权重淡入淡出，从当前姿态和速度继续；不能取消旧片段回到初始帧。快速输入增加有上限、随时间衰减的冲量，不排队堆积动作。
5. **骨架与形变**：显式 parent、局部静止变换、转轴、长度、角度/拉伸上限。角色根节点负责舞台位置；身体重心/躯干、头脸、双翅、双腿、尾羽、羽冠分层。每个面部特征使用固定局部锚点。两段肢体用端点目标求关节角（IK）；锁定支撑脚，迈步脚走弧线。拖拉翅尖先弯肢体，再带动躯干；限制拉伸，身体不会被几块独立 transform 撕开。大形变靠共享边界/骨骼权重，不能仅靠接缝重叠遮掩。
6. **渲染适配**：只接收最终 Pose/Deformation，一帧写一次。HTML 不承担物理。底层应可换 SVG 或骨骼蒙皮运行时，业务输入与行为不依赖选择器。环境物体也有锚点、动作权限和变换，接触在统一舞台坐标求解。

## 数据与执行顺序

建议目录（未来逐步迁移，不先建空壳）：

- `phoenix/rig.ts`：骨架、锚点、限制、渲染绑定
- `phoenix/input.ts`：指针与键盘，点击/拖拽判定
- `phoenix/intent.ts`：语义反应、注意力、上下文
- `phoenix/mixer.ts`：层权重、表达组、优先级和释放
- `phoenix/solver.ts`：弹簧、IK、脚底接触、形变限制
- `phoenix/locomotion.ts`：舞台路径、步幅、支撑脚与朝向
- `phoenix/environment.ts`：信封、纸张、对话气泡的可交互锚点
- `phoenix/render-svg.ts` / 后续骨骼渲染适配
- `phoenix/runtime.ts`：唯一时钟、生命周期和可注入随机源

每帧：收集输入 → 更新意图 → 产生动作目标 → 混合 → 受控时间步推进动态 → 应用骨长/脚底/形变约束 → 计算世界变换和命中几何 → 渲染。约束要在混合和动态之后复核，不能只限制动画关键帧。姿态和速度存在引擎数据中，不从 DOM 反解。

## 拖拽、走动、转身怎样做

- **摸脸**：双眼放松、双颊轻红、嘴保持自然，躯干稍向触点反方向躲；双翅小幅收拢。当前本轮已实现这一协调反应和方向参数。
- **拖拽**：保存抓住的局部点，目标为鼠标处，而不是瞬移根节点；用受限弹簧/IK 跟随。轻拉只局部变形，继续拉才移动重心或抬脚。释放时保留有限速度，超量能量耗散；从空中松手要落地吸收冲击。cancel、离开页面、窗口尺寸改变都收束约束，不能遗留抓取。
- **走动**：从目的地和速度推导步频/步幅。支撑脚在世界坐标锁定，身体前进时靠腿部求解保持接触，摆动脚抬起再落地。停下、反向都从当前步态过渡，不能水平平移一只原地踏步的图。仅在 hero 平台可行走区内，移动端重新计算边界，不盖住按钮。
- **转动**：身体倾斜/俯仰、小幅侧转先做。完整左右转身需要正面、四分之三侧面、侧面等姿态资源和遮挡顺序，完整背转还需背面素材。当前单视角 SVG 无法合理生成隐藏面，不用负缩放或极端 scaleX 冒充转身。
- **环境互动**：先注视 → 身体靠近/伸翅 → 接触或扇风 → 物体响应 → 收势。根据距离和方向计算力度；物体不能在凤凰尚未碰到或扇风前凭空启动。当前的信封/气泡联动仍是时间编排示范，尚不是空间接触系统。

## 技术选型

保留 SVG 做现有站点的轻量渲染和降级。先实现同渲染器无关的意图、Pose 和 Rig 接口。大幅弯曲/拖拽形变阶段，优先做一个 **Rive 骨骼/矢量蒙皮样机**（身体+单翅+双脚）与现有 SVG 对比，评估造型、输入响应、移动端负载后再决定迁移。Rive 提供骨骼、矢量控制点权重和关节绑定；它不替代角色意图、步态和接触逻辑。当前不引入新依赖，也不承诺无需补画即可自动导入成合格骨架。

若坚持纯 SVG，需要自己维护共享控制点形变、关节蒙皮与遮挡，成本明显高于现在的分组旋转。无须为了一个装饰角色引入完整刚体/布娃娃物理；采用受控卡通运动和必要约束更利于保持造型。

## 实施次序与验收门槛

A. 修正语义（本轮）：左右脸颊统一协调反应，保留方向参数。
B. 统一骨架/唯一姿态写入者：迁移 CSS 动作与 dataset 表情到混合器，保留静态首帧。
C. 单翅拖拽与形变样机：验证抓点跟随、限幅、连续松手和接缝；达标后扩展全身。
D. 地面接触与双脚步态：先原地重心移动/单步，再连续行走、停止与反向。
E. 补多视角素材后转身，再扩展空间性的环境互动。

每阶段保留可重放输入和可注入随机种子，录制鼠标轨迹/逐帧姿态用于复现。测试断言覆盖：关节距离误差、脚底滑动、拉伸上限、频繁反向的速度连续性、取消后无悬挂约束、跨帧率一致性；浏览器再检查表情逻辑、遮挡、触摸滚动、390px、深浅主题、无 JS 首帧与减少动态效果。性能门槛由目标设备实测确定；先记录当前基线，观察持续帧耗、长任务和离屏耗电，避免给出未经测量的帧率承诺。离屏/隐藏停止时钟，恢复不补算整段后台时间。
